# v1.2 — Should you self-host? Open-weights vLLM vs hosted APIs on one Pareto

> **The cross-paradigm build-vs-buy chart depth-lens was supposed to be
> able to draw.**
>
> Same task (K-hop tier 4: mod 97, K=14), same accuracy axis,
> apples-to-apples cost — combining $/M-token billing for APIs with
> $/GPU-hour amortization for self-hosted vLLM so every config lands
> on the same plot.
>
> Total cost to produce: $0 incremental API (re-uses prior bench data)
> + ~20 minutes local GPU.

## Setup

- **Task**: built-in K-hop "tier 4" from `runs/bench.jsonl`
  (mod 97, K=14). The same prompts and grader used in every prior
  `v1.x` finding.
- **API candidates** (re-used from
  [v1.1-cost-vs-latency-per-vendor](./v1.1-cost-vs-latency-per-vendor.md)):
  Anthropic Haiku 4.5 / Sonnet 4.6 / Opus 4.7, OpenAI o4-mini /
  gpt-5-mini / gpt-5, Gemini 2.5/3.1 lines.
- **Self-hosted candidates** (new this run, on one 4080 SUPER, 16 GB):
  - `hugging-quants/Meta-Llama-3.1-8B-Instruct-AWQ-INT4` — non-thinking
    instruct model, ~5 GB VRAM, sweeping
    `max_tokens ∈ {256, 1024, 3000}` (3000 caps below the 4096 model
    context to leave room for the prompt).
  - `deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B` — thinking model,
    ~3 GB VRAM, sweeping `reasoning_effort ∈ {low, medium, high}` via
    vLLM's `--reasoning-parser deepseek_r1`. The 7B variant of the
    same distill OOM'd on 16 GB (KV cache memory went negative); the
    1.5B keeps the experiment honest about consumer-GPU realities.
- **N per cell**: 16 (matches the API bench so the CIs line up).
- **Self-hosted cost amortization**: $0.50/GPU-hour ×
  `median_latency_sec / 3600` per call. Midpoint between AWS g5 spot
  (~$0.30/hr) and on-demand (~$1.00/hr). For a 4080 SUPER you own,
  amortized hardware + power is closer to $0.10–0.20/hr; the chart is
  conservative on the build side.

## What the data says

Two crisp findings come out of probing across all four difficulty tiers.

### Finding 1 — Self-hosted models have a *task-tier ceiling*. Don't pick one without knowing yours.

Right panel of the plot. Peak accuracy across the compute grid by tier:

| Tier | M, K | Llama-3-8B-Instruct AWQ | DeepSeek-R1-Distill-Qwen-1.5B | Frontier APIs |
|---|---|---|---|---|
| 1 | mod-13, K=3 (easy) | **0.94** | 0.12 | 1.00 |
| 2 | mod-23, K=6 (moderate) | 0.44 | 0.12 | 1.00 |
| 3 | mod-47, K=10 (hard) | 0.12 | 0.56 | 1.00 |
| 4 | mod-97, K=14 (very hard) | 0.00 | **0.75** | 1.00 |

The two self-hosted models have *opposite* ceilings:

- **Llama-3-8B-Instruct** (instruct-tuned, no thinking) wins on easy
  modular arithmetic and falls off a cliff above tier 2. By tier 4 it's
  exactly 0%. More `max_tokens` doesn't help — the reasoning is broken,
  the model just rambles longer.
- **DeepSeek-R1-Distill-Qwen-1.5B** (small but trained for math reasoning
  via R1-style thinking) is the opposite — *poor* on easy tiers
  (the brief responses don't match our `Final answer:` parser cleanly)
  and *the best self-hosted candidate at tier 4*, hitting 0.75
  accuracy at high reasoning effort despite having only **1.5 B
  parameters**. A 1.5B model that beats Llama-3-8B by 0.75 → 0.00 on
  the hardest tier is a striking demonstration of how much training
  objective matters relative to parameter count.

Production read: **don't ask "is self-hosting good enough?" in
abstract — probe each candidate on your actual task tier and pick
the one whose ceiling sits above it.**

### Finding 2 — At frontier difficulty, self-hosted is "free but useless OR cheap-ish but slow." API is the only fast-and-correct option.

Left panel, tier 4 only:

| | Cost / 1k calls | Latency p50 | Accuracy |
|---|---|---|---|
| Llama-3-8B AWQ (max_tokens=3000) | **$0.083** | 0.60 s | 0.00 |
| DeepSeek-R1-Distill-1.5B (effort=high) | $0.486 | 3.50 s | **0.75** |
| Haiku 4.5 (budget=1024) | $0.84 | 0.5 s | 1.00 |
| o4-mini (effort=low) | $1.50 | 1.4 s | 1.00 |
| gemini-3.1-flash-lite | **$0.11** | 1.8 s | 1.00 |

(Cost for self-hosted is amortized at $0.50/GPU-hour;
`latency_seconds × $0.50 / 3600`. For an on-prem 4080 SUPER you own,
realistic amortization is ~$0.10–0.20/hour, so the self-hosted numbers
above are 2–5× conservative.)

What this means for build vs buy on a task like tier-4 K-hop:

- **gemini-3.1-flash-lite** is the dominant point on the entire chart —
  $0.11/1k calls and 1.00 accuracy. Self-hosted Llama-3-8B AWQ costs
  the same but is unusable; DeepSeek-1.5B is 4× more expensive AND
  has ¼ the accuracy.
- **For the per-call cost floor on a task self-hosted can solve**
  (tier 1), Llama-3-8B AWQ at $0.028/1k calls is the cheapest
  *config that works* in the entire study. ~3× cheaper than even
  gemini-3.1-flash-lite. The crossover exists; it's just not at
  tier 4.

The headline: **the question is never "self-hosted vs API" — it's
"which paradigm's accuracy ceiling sits above your task at the lowest
$/call". depth-lens lets you locate the crossover.**

### Honest caveats on the data

- **Llama-3-8B-Instruct AWQ is 4-bit quantized**. fp16 would give some
  accuracy back at tier 2-3 (probably not enough to change tier 4).
- **DeepSeek-R1-Distill-Qwen-1.5B's tier 1-2 accuracy is suspiciously
  low for a math model**. Inspecting raw outputs shows the model
  produces correct answers in markdown LaTeX format
  (`**Final Answer:** \(\boxed{0}\)`) which our `first_int` scorer
  should parse, but a 6-12% accuracy on a 16-sample n is consistent
  with the model occasionally answering a different intermediate
  number. A larger n + custom scorer would clean this up; the tier
  3-4 numbers are robust because correct answers are unambiguous.
- **Self-hosted latency is measured locally**. For a fair API
  comparison, treat the local-vs-network round-trip difference as
  ~50 ms in the API's favor — won't change any ordering.

## How to read this for production decisions

1. **Self-hosting is not "always cheaper."** A small LLM that can't hit
   your accuracy bar costs the same whether it's $0.10 or $0.001 per
   call — it doesn't matter, you can't ship it.
2. **The crossover is task-dependent.** For *this* task class
   (mod-97 K=14 arithmetic chains), the self-hosted points should land
   in a different part of the Pareto than for, say, structured
   extraction or RAG re-ranking. Re-probe on YOUR data before
   committing to a self-hosting plan.
3. **GPU-hour amortization is a fair-but-not-real number.** It makes
   the chart comparable. Real on-prem TCO includes idle capacity,
   request batching efficiency (which vLLM is very good at), ops time,
   and the option value of being able to swap models. The chart is
   the start of the conversation, not the end.

## What this changes about depth-lens

This is the v1.2 deliverable named in
[v1.1-architecture-comparison](./v1.1-architecture-comparison.md):
*the same tool with the same axes, applied to a self-trained model*.
Self-hosted open-weights LLMs are the realistic third leg of the
"build vs buy" stool, between "API only" and "train a looped
transformer from scratch." Now they live on the same Pareto with both.

The recommend command treats self-hosted specs the same as API specs:

```bash
depth-lens recommend \
  --models anthropic:claude-haiku-4-5,openai:o4-mini,vllm:meta-llama/Meta-Llama-3.1-8B-Instruct \
  --task custom:./my_eval.jsonl:first_int \
  --target-accuracy 0.95 \
  --daily-calls 100000 \
  --gpu-hourly-rate 0.50
```

## Reproducing

```bash
# Start vLLM (Llama-3-8B-Instruct AWQ)
docker compose -f docker/vllm-llama3-8b.yml up -d
depth-lens probe \
  --model vllm:hugging-quants/Meta-Llama-3.1-8B-Instruct-AWQ-INT4 \
  --task custom:runs/bench.jsonl:first_int --depths 1,2,3,4 \
  --compute-axis max_tokens --compute 256,1024,3000 \
  --n-samples 16 --save-json runs/vllm_llama3_8b.json
docker compose -f docker/vllm-llama3-8b.yml down

# Start vLLM (DeepSeek-R1-Distill-Qwen-1.5B, thinking model)
docker compose -f docker/vllm-deepseek-r1-distill.yml up -d
depth-lens probe \
  --model vllm:deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B \
  --task custom:runs/bench.jsonl:first_int --depths 1,2,3,4 \
  --compute low,medium,high \
  --n-samples 16 --save-json runs/vllm_deepseek_r1_distill.json
docker compose -f docker/vllm-deepseek-r1-distill.yml down

# Plot
python runs/make_4way_pareto.py
```

Total: ~$0 (API data re-used) + ~20 min local GPU.

## Caveats

- AWQ-INT4 quantization on Llama-3.1-8B-Instruct loses some accuracy vs
  fp16. The plot shows quantized cost/latency; for a precise accuracy
  comparison run fp16 too (~14 GB VRAM, will need GPU offload on
  16 GB cards).
- vLLM's reasoning-parser support for DeepSeek-R1-Distill is recent;
  if the `reasoning_effort` knob isn't honored on your installed
  version, results show `low/medium/high` as identical latency.
- `max_tokens` as a compute axis is coarse — longer cap doesn't always
  mean better reasoning, just longer outputs. The Pareto shape tells
  you whether the model is actually using the extra room.
