# v1.0 — Translating the K-hop bench into $-savings

> Same data as [`v1.0-cross-vendor-summary.md`](./v1.0-cross-vendor-summary.md),
> read through a production-cost lens. The headline claim depth-lens lives or
> dies by: *"how much would switching tiers actually save you?"*

## Setup

- **Task class**: structured composition / extraction of the shape probed by
  K-hop modular arithmetic at tier 4 (mod 97, K=14). If your prompts look
  like this (multi-step deterministic reasoning over short text), the
  numbers below apply directly. If they don't, run the bench on **your**
  data — see [`docs/playbook/cost-audit.md`](../playbook/cost-audit.md).
- **Accuracy target**: 1.00 on this task (every model tested achieves it
  at every budget — see source bench).
- **Volume assumed**: 10,000 calls/day = 3.65M calls/year (typical for a
  mid-sized SaaS feature).

## What it costs you to route to each tier

Cost / call, cheapest passing setting per model, at K-hop tier 4:

| Vendor / model | Cheapest passing config | $/call | $/day @ 10k | $/year |
|---|---|---:|---:|---:|
| **Anthropic Haiku 4.5** | `budget=1024` | ~$0.001 | ~$10 | **~$3,650** |
| OpenAI gpt-5-mini | `effort=low` | $0.0012 | $12 | $4,380 |
| OpenAI o4-mini | `effort=low` | $0.0036 | $36 | $13,140 |
| **Anthropic Sonnet 4.6** | `budget=1024` | ~$0.005 | ~$50 | **~$18,250** |
| OpenAI gpt-5 | `effort=low` | $0.0065 | $65 | $23,725 |
| **Anthropic Opus 4.7** | `budget=1024` | $0.0206 | $206 | **~$75,190** |
| Anthropic Opus 4.7 | `budget=16384` | $0.0347 | $347 | $126,655 |

(Anthropic Haiku/Sonnet $/call values are estimated — see [Caveats](#caveats)
for why those got dropped from the per-cell capture in this run.)

## The 4 production "savings switches" depth-lens surfaces

### 1. Opus 4.7 → Haiku 4.5 (when Haiku ceiling-saturates your task)

```
Opus @ budget=16384  ($347/day) → Haiku @ budget=1024 ($10/day)
                                                       ──────
                                            saves     $337/day
                                            =       ~$123k/year   (97% reduction)
```

This is the canonical "stop paying for what you don't need" switch.
**Every** model tested aced K-hop tier 4; if your task is in this
saturation regime, only the price changes when you switch tiers.

### 2. Opus 4.7 budget=16384 → Opus 4.7 budget=1024

```
Opus @ 16384 ($347/day) → Opus @ 1024 ($206/day)
                                       ──────
                              saves   $141/day
                                    =  ~$51k/year   (41% reduction)
```

For tasks where you *do* need the Opus tier, **default thinking budgets
of 16k are a strict cost loss when 1k achieves the same accuracy**.
This was the unambiguous finding across every Anthropic / OpenAI cell
in the bench (see finding #1 in the cross-vendor summary).

### 3. gpt-5 → gpt-5-mini (within the OpenAI line)

```
gpt-5 effort=low ($65/day) → gpt-5-mini effort=low ($12/day)
                                                    ─────
                                          saves    $53/day
                                                = ~$19k/year   (82% reduction)
```

…with a 3× latency hit. Worth it if your users tolerate ~3-4s response
times; not if your UI gates on sub-second.

### 4. o4-mini → gpt-5-mini (if latency tolerates)

```
o4-mini effort=low ($36/day) → gpt-5-mini effort=low ($12/day)
                                                     ─────
                                            saves   $24/day
                                                  = ~$8.7k/year   (66% reduction)
```

gpt-5-mini is per-token cheaper but per-call slower. The
[OpenAI cross-vendor doc](./v1.0-openai-cross-vendor.md) has the latency
table.

## Practitioner rules these numbers encode

1. **Default to the cheapest passing config and only escalate on evidence.**
   The instinct to pick Opus is paying for ceiling capacity you can't
   actually use on most tasks.
2. **Set `thinking_budget=1024` (or `reasoning_effort=low`) as the prior**,
   raise only when measurable accuracy gain justifies the cost. This is
   the single biggest source of waste depth-lens surfaces.
3. **Re-evaluate when the vendor ships a new model.** See
   [regression-detection.md](../playbook/regression-detection.md).
4. **Run on YOUR data.** This page's numbers come from a synthetic
   K-hop bench. For your numbers, see
   [cost-audit.md](../playbook/cost-audit.md).

## Caveats

- Anthropic per-cell cost numbers came out as `(n/a)` on the original
  bench run because of an adapter-side usage-capture gap (Anthropic
  reports usage in a slightly different shape than OpenAI). The $/call
  estimates in the Haiku/Sonnet/Opus rows are derived from per-cell
  token counts captured for Opus + Anthropic's published price card —
  cross-checked but not first-class measured. Fix coming in v1.1.
- Volumes are illustrative. If you run 100k calls/day, multiply all $
  numbers by 10. If your task DOESN'T ceiling-saturate, the cheapest
  tier won't qualify and the savings shrink.
- The same logic applies to API-cost-only thinking — local inference
  (vLLM, OpenMythos) has different cost structure (GPU time, not API
  tokens) and would need its own analysis.

## Reproducing

```bash
# Anthropic recommend on your data
depth-lens recommend \
    --models anthropic:claude-haiku-4-5,anthropic:claude-sonnet-4-6,anthropic:claude-opus-4-7 \
    --task custom:./your_data.jsonl:first_int \
    --target-accuracy 0.97 \
    --daily-calls 10000

# Cross-vendor recommend
depth-lens recommend \
    --models anthropic:claude-haiku-4-5,openai:gpt-5-mini,openai:o4-mini,gemini:gemini-3.1-flash-lite \
    --task custom:./your_data.jsonl:first_int \
    --target-accuracy 0.97 \
    --daily-calls 10000
```
